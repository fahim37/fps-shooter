# Desert City handoff

Where the Desert City map stands, for picking the work up in a new session on another PC.
Written 2026-11-04.

## How the map is built

The map comes from a finished level exported as one GLB (`assets-raw/desert-city/source/map.glb`, not in git, so it must be on the PC to re-import). Three things about it cause most problems:

- **Walls are one-sided shells.** Buildings are hollow. From behind, a wall is invisible.
- **The original terrain was lost in the export.** `terrain()` in `scripts/assets/desert.ts` rebuilds it by guessing, which makes sand humps and pits.
- **Some walls stood on that lost terrain,** so they hang above the rebuilt ground.

Anything that lets a player behind a wall or onto rebuilt sand looks unfinished. All our additions live in `ROUTES` in `scripts/assets/desert-routes.ts`:

| `ROUTES` key | What it does |
|---|---|
| `stairs` | Solid stairs with a ramp for collision |
| `doors` | Doorways cut through walls |
| `flat` | Forces the rebuilt terrain to a height or slope |
| `blocks` | Solid concrete masses |
| `paving` | Paved ground, flat or sloped |
| `walls` | Plaster walls matching the town |
| `inside` | Zones where walls also get inner faces |

Rebuild with `npx tsx scripts/import-assets.ts desert`.

## How to check a change

Tests alone missed real bugs on this map, including walkable holes. After changing collision or routes, also check:

- **Reachable space:** flood out from every spawn using the real `Mover` from `game/shared/movement.ts`, with sprint jumps. The navmesh only knows bot routes. Players should never reach the rebuilt sand.
- **Stuck in floors:** at each reachable spot, cast down against both collision and the visible GLB meshes. A visible floor more than 0.3 m above the feet means a hole.
- **Floors against the last build:** compare floor heights so a removed landing shows up.
- **See-through walls:** from reachable spots, count eye-level rays that hit the back of a triangle.
- **Look at it:** `/dev/map?map=desert&cam=x,y,z&target=x,y,z&quality=low` shows a view, and `plan=x,z,width&clip=height` shows a plan slice. Put the camera above the ground at that spot, because terrain height varies and a low camera sits underground.

**Finding a spot from a photo:** the minimap is centred on the player and turned to their facing, so match its shapes against the footprints in `desert-pieces.json`. The footprints don't show levels, so ask which floor they're on.

Run `npm test`. Coordinates: x runs east, z runs south (north is -z), y is up. Blue spawns west, Red east.

## Deploying

Deploy only when asked, and commit straight to `main`. Before pulling or deploying, review incoming commits, because the GitHub repo was compromised once in November 2026: look for hidden long lines, `package.json` script changes and `.vscode/tasks.json`.

On the server, build in a separate git worktree with `NEXT_PUBLIC_BASE_PATH=/fps npm run build`, point the `.next` symlink at a new `.next-release-<sha>`, then restart both apps with PM2. Restarting ends live matches, so check the server's `/rooms` first. The office PC may not have the server's SSH key.
